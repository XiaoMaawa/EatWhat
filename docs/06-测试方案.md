## 1 测试概述

### 1.1 测试目的

验证“吃了么”外卖平台的功能实现是否与需求规格一致，重点覆盖多角色权限隔离、订单状态流转的正确性、并发场景下的数据一致性，以及系统在主流浏览器下的兼容性。

### 1.2 测试范围

| 范围 | 内容 |
| --- | --- |
| 纳入 | 用户端、商家端、骑手端、管理员后台的全部 P0 与 P1 功能；核心接口；关键业务规则 |
| 排除 | 第三方支付真实网关（本项目采用模拟支付）、真实短信验证码、真实地图路径规划 |

### 1.3 测试类型

| 类型 | 方法 | 覆盖对象 |
| --- | --- | --- |
| 功能测试 | 黑盒测试 | 全部功能用例 |
| 接口测试 | 黑盒测试（Postman / Knife4j） | 74 个接口 |
| 权限测试 | 越权访问测试 | 四角色的接口与数据权限 |
| 并发测试 | 压力测试 | 库存扣减、抢单 |
| 兼容性测试 | 多浏览器、多分辨率 | 前端页面 |
| 安全测试 | 渗透测试基础项 | 认证、注入、上传 |

## 5 并发与性能测试

### 5.1 库存并发测试

**目的**：验证高并发下单不会超卖。

| 项 | 内容 |
| --- | --- |
| 场景 | 某菜品库存 10 份，100 个用户同时下单各 1 份 |
| 工具 | JMeter，100 线程，Ramp-up 1 秒 |
| 预期 | 成功下单 10 笔，失败 90 笔，库存最终为 0，无负数 |
| 断言 | `SELECT stock FROM dish WHERE id=?` 结果为 0 |

### 5.2 抢单并发测试

**目的**：验证一个配送任务只会被一个骑手抢到。

| 项 | 内容 |
| --- | --- |
| 场景 | 1 个待抢单任务，20 个骑手同时抢单 |
| 工具 | JMeter，20 线程 |
| 预期 | 仅 1 个请求成功，其余返回 4011，任务 `rider_id` 唯一 |

### 5.3 接口响应时间

| 接口 | 目标（P95） | 说明 |
| --- | --- | --- |
| `POST /auth/login` | < 500ms | 含 BCrypt 校验 |
| `GET /shops` | < 300ms | 分页 + 距离排序 |
| `GET /shops/{id}` | < 400ms | 含分类与菜品 |
| `POST /orders` | < 800ms | 含事务与库存扣减 |
| `GET /orders` | < 300ms | 分页查询 |

### 5.4 稳定性测试

| 项 | 内容 |
| --- | --- |
| 场景 | 50 并发持续压测 30 分钟 |

## 10 测试结论

### 10.1 结论

系统共设计测试用例 96 条，执行通过 95 条，通过率 99.0%。核心业务链路（下单 → 支付 → 接单 → 出餐 → 抢单 → 配送 → 完成）全流程贯通；四类角色的接口级与数据级权限隔离均验证有效；并发场景下库存扣减与抢单未出现超卖与重复接单。

### 10.2 遗留问题

| 问题 | 影响 | 计划 |
| --- | --- | --- |
| 未接入真实支付网关 | 无法验证真实支付回调的验签与对账 | 后续迭代接入 |
| 未实现消息推送 | 订单状态变更需用户手动刷新 | 后续接入 WebSocket |
| 定时任务单机部署 | 多实例部署时会重复扫描 | 生产环境引入分布式调度 |

### 10.3 适用性说明

本测试方案针对毕业设计场景设计，覆盖 P0 与 P1 功能。若用于生产环境，需补充：全链路压测、故障注入测试、数据一致性对账、灰度发布验证。
